Guide de mise en route WIN natif — lot 0 23 août 2026

Du VPS à l'APK

Mettre la nouvelle API en ligne à côté de l'ancienne, puis installer l'application sur votre téléphone Android. Environ trois heures, dont une d'attente pendant la compilation.

Rien de ce qui suit ne touche à la v83. La nouvelle API écoute sur un autre port, répond sur une autre adresse, et écrit dans une autre base de données. Si quelque chose se passe mal, l'étape 12 remet tout comme avant en deux commandes.

Ce que Nginx servira après l'opération

/→index.html de la v83 — inchangé
/api/→ancien backend, port 3001 — inchangé
/uploads/→photos de la v83 — inchangé
/valhalla/→conteneur de routage, port 8002 — inchangé
/v2/→nouvelle API, port 3002 — c'est tout ce qu'on ajoute

Le port 3002 n'est ouvert que sur 127.0.0.1 : seul Nginx peut lui parler. Rien à changer dans le pare-feu.

01

Sauvegarder avant de toucher à quoi que ce soit

5 min

Sur le VPS, via PuTTY

# les données de l'ancien backend, et la configuration de Nginx
cd ~ && mkdir -p sauvegardes
cp -r ~/winbackend/data ~/sauvegardes/data-$(date +%F)
sudo cp /etc/nginx/sites-available/default ~/sauvegardes/nginx-default-$(date +%F).bak

# vérifier que Docker est bien là (Valhalla tourne déjà avec)
docker --version
docker compose version

Si docker compose version répond une erreur, installez le greffon : sudo apt install -y docker-compose-plugin.

02

Envoyer le code sur le serveur

5 min

WinSCP, puis PuTTY

Déposez win-native-lot0.zip dans /home/ubuntu/ avec WinSCP, puis :

cd ~ && mkdir -p win-native && cd win-native
unzip -o ~/win-native-lot0.zip
ls
Vérifiez le dossier avant de décompresser

Le -o écrase sans demander. Il doit être lancé depuis ~/win-native et nulle part ailleurs — surtout pas depuis ~/winbackend, où il effacerait vos adresses.

03

Écrire la configuration

10 min

Sur le VPS

Deux fichiers : un pour le mot de passe de la base, un pour l'API.

# 1. mot de passe de la base de données
cd ~/win-native
cp .env.example .env
openssl rand -base64 32          # copiez le résultat
nano .env                        # collez-le dans POSTGRES_PASSWORD

# 2. configuration de l'API
cd ~/win-native/apps/api
cp .env.example .env
openssl rand -base64 48          # copiez le résultat
nano .env

Dans apps/api/.env, seules trois lignes comptent vraiment :

JWT_SECRET=<la valeur générée par openssl>
PUBLIC_BASE_URL=https://51.77.194.25.nip.io/v2
NODE_ENV=production

Laissez DATABASE_URL et REDIS_URL tels quels : le fichier docker-compose.yml les remplace automatiquement par les adresses internes des conteneurs.

Pourquoi c'est mieux qu'avant

Si une variable manque ou si JWT_SECRET est trop court, l'API refuse de démarrer et vous dit laquelle. L'ancien backend, lui, démarrait à moitié configuré et vous ne le découvriez que plus tard.

04

Construire et démarrer

10 min

Sur le VPS

cd ~/win-native
docker compose up -d --build

docker compose ps                # les trois services doivent être "running"
docker compose logs -f api       # Ctrl+C pour sortir des logs

Vous devez voir Base prête, PostGIS 3.5 puis Server listening. Premier contrôle, depuis le VPS :

curl -s http://127.0.0.1:3002/status

Réponse attendue : {"ok":true,"service":"win-api",...}

05

Créer les tables

2 min

Sur le VPS

docker compose exec api node dist/src/db/migrate.js

Affiche + 0000_init.sql puis 1 migration(s) appliquée(s). Relancer la commande ne casse rien : elle saute ce qui est déjà passé.

06

Reprendre vos adresses existantes

15 min

Sur le VPS

Sans cette étape, l'application s'ouvrira sur une carte vide. Les données de l'ancien backend sont déjà sur le serveur : on les monte en lecture seule dans le conteneur, elles ne peuvent donc pas être abîmées.

# d'abord à blanc : aucune écriture, juste un rapport
docker compose run --rm \
  -v /home/ubuntu/winbackend/data/db:/legacy:ro \
  api node dist/scripts/migrate-legacy.js --source /legacy --dry-run

Lisez le tableau : combien d'enregistrements lus, combien importables, et lesquels sont écartés avec la raison. On ne passe à la suite que quand ce rapport vous paraît juste. Ensuite seulement :

docker compose run --rm \
  -v /home/ubuntu/winbackend/data/db:/legacy:ro \
  api node dist/scripts/migrate-legacy.js --source /legacy
Si le rapport écarte beaucoup de lignes

C'est le signe que les noms de champs de vos JSON diffèrent de ceux que le script attend. Envoyez-moi le rapport : j'ajuste la correspondance, c'est cinq minutes de travail. N'importez pas un fichier à moitié.

07

Créer votre compte administrateur

3 min

Sur le VPS

docker compose run --rm api node dist/scripts/seed-admin.js \
  --email vous@exemple.dz --name "Amiir" --role admin

Le mot de passe est demandé au clavier, jamais écrit dans la commande — sinon il resterait dans l'historique du shell. Douze caractères minimum. Ce compte remplace le code 1154, qui était écrit en clair dans index.html et donc lisible par n'importe qui.

08

Ouvrir la route dans Nginx

10 min

Sur le VPS

cat ~/win-native/deploy/nginx-win-v2.conf     # le contenu à coller
sudo nano /etc/nginx/sites-available/default

Collez les deux blocs location à l'intérieur du bloc server qui écoute en 443, juste avant son accolade fermante. Ne modifiez aucune ligne existante.

sudo nginx -t                    # doit répondre "syntax is ok" et "test is successful"
sudo systemctl reload nginx
L'ordre des deux blocs compte

/v2/socket.io/ doit être écrit avant /v2/. Nginx choisit le préfixe le plus long, donc l'ordre importe peu en théorie — mais gardez-le, c'est ce qui rend le fichier lisible quand vous y reviendrez dans six mois. Sans ce premier bloc, les signalements en temps réel n'arriveront jamais sur le téléphone.

09

Vérifier — et vérifier que l'ancienne vit toujours

5 min

Sur le VPS

# la nouvelle API
curl -s https://51.77.194.25.nip.io/v2/status
curl -s https://51.77.194.25.nip.io/v2/status/full
curl -s "https://51.77.194.25.nip.io/v2/places/search?q=pharm" | head -c 300

# LE contrôle qui compte : la v83 doit répondre exactement comme avant
curl -s https://51.77.194.25.nip.io/api/status
curl -s "https://51.77.194.25.nip.io/api/addresses/search?q=a" | head -c 200

/v2/status/full vérifie aussi Valhalla. S'il répond "valhalla":{"ok":false}, le routage est en panne — mais la carte et les signalements fonctionneront quand même.

10

Préparer la compilation sur votre PC

20 min

Sur Windows, dans PowerShell

Il faut Node 22 ou plus : nodejs.org, version LTS. Vérifiez avec node -v. C'est le seul prérequis — ni Android Studio, ni le SDK Android, qui représenteraient une dizaine de gigaoctets de téléchargement.

Créez un compte gratuit sur expo.dev, puis :

cd C:\Users\user\Desktop\WINDZ\win-native\apps\mobile
.\build-apk.ps1

Le script fait tout dans l'ordre : vérifier Node, installer les dépendances, compiler la partie partagée, mettre en place eas-cli, vous connecter, créer le projet chez Expo au premier lancement, puis lancer la compilation.

Deux messages qui inquiètent à tort

Si PowerShell refuse d'exécuter le script, lancez d'abord Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass dans la même fenêtre.

Si EAS signale que le dossier n'est pas un dépôt Git, répondez oui pour continuer. Vous pouvez aussi faire git init && git add . && git commit -m "lot 0" — ce serait de toute façon une bonne idée avant le lot 1.

11

Récupérer l'APK et l'installer

20 à 45 min d'attente

Sur Windows, puis sur le téléphone

La compilation ne se fait pas sur votre PC. Le code est envoyé chez Expo, qui compile sur ses machines et vous renvoie un lien de téléchargement et un QR code. Vous pouvez fermer la fenêtre pendant l'attente : le travail continue, et le lien reste disponible sur expo.dev, section Builds.

Ensuite, sur le téléphone :

  1. Ouvrez le lien (ou scannez le QR code) et téléchargez le fichier .apk.
  2. Android demandera d'autoriser l'installation depuis cette source — acceptez.
  3. Au premier lancement, accordez l'accès à la position « pendant l'utilisation ». L'autorisation d'arrière-plan ne servira qu'au lot 3.
Ce que vous devez voir

La carte de l'Algérie, votre position bleue après quelques secondes, le bouton ◎ qui recentre, et — si vous avez fait l'étape 6 — vos signalements permanents affichés en pastilles ambre. Le bandeau du haut annonce combien il y en a autour de vous.

Test du temps réel : ajoutez un signalement depuis la v83 sur votre ordinateur, il doit apparaître sur le téléphone en une seconde, sans rien rafraîchir.

L'adresse du serveur est figée dans l'APK

Elle est lue dans app.json, ligne apiBaseUrl, au moment de la compilation. Si vous changez de nom de domaine plus tard — en remplaçant nip.io par un vrai domaine, par exemple — il faudra recompiler un APK. Ce n'est pas grave, mais mieux vaut le savoir avant de distribuer le fichier à douze testeurs.

Rien ne vous empêche de compiler l'APK avant d'avoir déployé le serveur : la carte, le fond de plan et votre position fonctionneront. Seuls les lieux et les signalements resteront vides tant que /v2/ ne répond pas.

12

Revenir en arrière, si besoin

3 min

Sur le VPS

cd ~/win-native
docker compose down

sudo cp ~/sauvegardes/nginx-default-<date>.bak /etc/nginx/sites-available/default
sudo nginx -t && sudo systemctl reload nginx
Jamais l'option -v

docker compose down -v supprime aussi les volumes, donc la base de données et toutes les photos envoyées. docker compose down seul arrête les conteneurs et garde tout.
